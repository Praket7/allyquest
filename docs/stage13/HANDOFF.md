# Ally Quest — Stage 13 engineering handoff

## Baseline and objective
The authoritative baseline for this pass was the user's uploaded `Ally_Quest_Welcome_Street_Production_Improvement_Playable(1).html`, not the older Stage 9 remote. This game is K12Allergies' 2.5D platform adventure for roughly ages 7–12. The approved home, five Welcome Street missions, art identities, obstacle layout, and educational safety principles must remain. Do not return to drag-and-drop-only courses or flattened screenshot overlays. The original vision is 12 worlds with 25 levels each (300 planned, not implemented). Current content is five levels, not 300. Repo: https://github.com/Praket7/allyquest. Branch: `stage13-ui-animation-stabilization`. Stage 9 main baseline: `a1340d0b14d9e9e4c695bb6083061f98571f3d25`.

## Stage 13 changes
- Shared physical controller, run animation keyed to distance, character-specific stride frame order, discrete rather than ghosted crossfades, separate ascent/fall/landing/idle poses, foot anchor at 247/256, grounded shadow and landing reaction. Ethan, Maya, Leo and Ari use the same movement parameters. Existing eight poses retained; this is not a full skeletal animation system.
- Crew selector responsive grid, selected state and accessible buttons; reworked map, HUD and comic bounds; scrollable modal and footer; keyboard/native button behavior, touch sizing, focus/input isolation, clear held keys on blur and level changes; prevent duplicate self-conversation, hide tutorial during dialogue, guard checkpoint and interaction vertical proximity.
- Preserve all five levels and eight station minigames, fictional package evidence, adult verification and non-food inclusive activities. Keep art and physics separate, do not replace playable geometry with decorative pictures.

## Evidence and limits
Four Chromium viewport profiles (1440×900, 390×844, 844×390, 320×568), four characters each, 16 measured runs: each reached identical 197 world-unit jump apex in fixed-step QA samples, returned grounded and selected ascent/fall frames; real keyboard jump, selection, settings/pause and dialogue bounds checked. QA position injection and deterministic ticks are used, not sixteen uninterrupted human playthroughs. No uncaught errors in these runs. Existing production report supplied by user includes eight stations tested on desktop and mobile, but not all of those prior test results automatically apply to this revision. Child playtests, specialist approval, device FPS, Safari/WebKit and Android field performance remain unverified. No claim that the game is educationally effective or medically certified. QA APIs must remain opt-in only.

## Next stages and acceptance gates
These are proposed continuation stages, not completed tasks. Make one excellent, longer five-level vertical slice before adding dozens of short repetitive courses.

14. Complete input/animation validation: real keyboard/touch paths for every hero, spring/gap/moving-platform trajectories, pointer cancellation, focus, all menus, repeated pause/resume, device rotation. Test selected hero across restart/map/next level; no duplicated NPC identities. Add visual snapshot baselines for all critical screens; tune animation at 60/120 Hz and low frame rates. Measure real-device frame time before claiming performance.

15. Expand Welcome Street 1–5 to meaningful 3–8 minute adventures, with safe practice, a midlevel discovery, a two-step mechanic, meaningful optional routes, checkpoint, payoff. School: discover missing banner through clues and physical tasks. Cafeteria: guide cart, route moving stations, equipment-return logic and trusted adult handoff. Label Lab: magnifier, compare current fictional packages and locate evidence before adult verification. Garden: lever and bridge plus building an inclusive activity space. Celebration: combine previously learned mechanics, visible transformation, optional exploration. Avoid more empty running distance. Make level goals and obstacles visually readable; no arbitrary timer penalties.

16. Establish data-driven content tooling: schema validation, coordinate/collision checks, objective prerequisite graph, deterministic physics runner, level editor, art manifest, scripted full input paths without completing tasks by debug hook. Add end-to-end tests and CI for source compilation, reproducibility, full missions, keyboard/touch and visual regression. Establish canonical editable repo and archive old releases.

17. Educational and usability validation: pediatric allergy educator and school-health professional review all statements; teachers and children test age-appropriate comprehension, inclusion, reading, independent play, enjoyment and voluntary replay. Use consent and data minimization; avoid storing allergies or unnecessary child identifiers. Never teach children to independently certify food safety; follow individual plan and responsible adult. Record observed defects, revise, retest.

18. Complete Welcome Street 6–25 in four batches: experiment (6–10), surprise (11–15), combine (16–20), mastery (21–25). Each batch must introduce distinct physical choices and meaningful rewards, not just longer paths. Publish only after full playable acceptance and specialist content review.

19. Expand worlds in polished batches: Cafeteria Circuit (conveyors), Birthday Boulevard (switches), Picnic Park (bridges), Label Lab (evidence), Camp Compass (cooperation), Carnival Coast (chain reactions), Cinema Square (mechanisms), Sports Stadium (routing), Mystery Museum (investigation), Friendship Festival (team abilities), Grand Celebration (combined finale). Original target is 25 levels per world; scope according to demonstrated quality. Create a real daily puzzle bank and earned clubhouse decorations without streak pressure, ads or paywalls.

20. Production release: cross-browser/mobile accessibility, reduced motion, audio controls, text readability and input alternatives; performance profiling on school Chromebooks, privacy and COPPA review before child accounts/telemetry, security and offline save recovery, hosting at K12Allergies, content/version management, parent/teacher guidance, human support. No public child chat. Launch only after independent playtesting and specialist approval.

## Release procedure
Branch from current verified main; make a feature PR, inspect exact head SHA, run existing and new checks, inspect failures and fix rather than bypass, merge only when all expected checks pass and exact tested head is unchanged. Verify the merged main workflow and publish a reproducible standalone, source and QA report. Do not delete Stage 9 history. Do not claim green from local tests alone.
